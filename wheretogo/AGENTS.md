# 《今天去哪？》專題協作規則

## 技術與產品範圍

- 本專題為《今天去哪？》Android App，採 Kotlin、XML 與 Room。
- 依使用者提供的最新版企畫書開發，不擅自增加功能。若無法取得或確認企畫書版本，先確認需求再實作。
- UI 示意圖僅代表設計方向，不代表對應功能已完成。
- 維持零付費、不綁信用卡；不引入付費 API、需綁信用卡或試用後收費的服務。

## 工作方式與修改範圍

- 每次只完成一個主要任務，操作前簡述目的及驗收方式。
- 修改僅限目前的 `wheretogo` 專案，不變更上層 HW1～HW5。
- 保留 Git 歷史，不使用破壞性 Git 指令，例如 `reset --hard`、`clean`、強制推送或未經指示重寫歷史。
- 可自主修改程式、修復錯誤、執行建構與測試，不必逐步等待確認。
- 完成一個可獨立驗證的功能或修正，先驗證，再依結果決定是否自行 commit；只加入本次任務的明確檔案，不使用 `git add .`，不提交 HW.zip、快取、金鑰或無關變更，保留使用者未提交的工作。
- 本次不授權 push、強制推送、重寫歷史或破壞性清理。
- 每個功能必要驗證後建立範圍明確的本機 commit；不將其他未驗證歷史修改一併提交。中斷後先檢查 Git 與現有程式，不重做既有功能。
- 同一問題最多自主修復三次；避免不必要的全專案掃描或完整建構。
- 每階段先驗證，再依結果決定提交與下一階段；編譯、單元測試、裝置測試與人工操作分別回報。受阻時可繼續不依賴該驗證的工作，但不得宣稱驗收完成；若缺少驗證已使後續工作不可靠，保存進度並回報必要操作。
- 不清除 App 資料、不重建專案來迴避錯誤。

## 開發順序與自主決策

1. 確認並修復登入／註冊閃退。
2. 驗證帳號建立、重複帳號、登入、狀態保留及登出。
3. 依正式企畫書與已確認的 A～H UI，逐階段完成其餘功能。
4. 最後進行整合驗證與展示流程檢查。

- 僅在文件與實作衝突且會改變使用者行為、缺少無法合理決定的關鍵需求，或涉及付費、帳號／憑證、不可逆操作及必要權限時詢問。
- 一般命名、程式結構與可逆實作細節自行決定；不擅自新增功能。
- 每個主要階段簡短回報結果後，繼續下一個可進行的已授權任務。
- 重大需求、架構變更或可能造成資料遺失的操作須先詢問使用者；一般可逆技術細節自行決定。

## 工作階段開始

1. 讀取本檔與 `docs/DEVELOPMENT_STATUS.md`，檢查 `git status` 和最近提交。
2. 確認已完成、未完成及待驗證項目，選擇下一項安全的工作；避免重複實作。

## 低記憶體環境與測試策略

- Windows 11、VS Code、Codex，實體記憶體 16 GB，不以升級硬體作為方案。不得自行啟動 Android Studio GUI；必要時由使用者手動開啟。日常不啟動模擬器。
- 使用 Gradle Wrapper CLI，優先 `--no-daemon --max-workers=1`；不得同時執行多個 Gradle 建構，先確認其他背景建構已結束。高記憶體工作啟動前檢查可用 RAM，低於 2 GB 時暫停並回報。
- 每項工作依範圍執行編譯、單元測試及靜態檢查；必要的裝置測試可集中安排，不因節省資源跳過，未執行須標為待驗證。模擬器 offline 時記錄問題，繼續不依賴裝置的工作。
- 保留既有 Pixel 8、其 App 資料與獨立 QA applicationId 配置。裝置測試前確認裝置與目標套件名稱；不擅自登出、清除資料、Wipe Data、重設或覆蓋既有模擬器資料。測試後只有確知由本次任務啟動且無未儲存資料風險時才可關閉。

## 進度保存

- 持續於 `docs/DEVELOPMENT_STATUS.md` 記錄已完成、驗證證據、未完成、阻礙及下一步。
- 每個功能或重要階段及工作結束前更新下一個優先項目；記錄問題的影響與處理方式，以及實際測試指令、日期及結果。保持簡潔，歷史詳見 `docs/DEVELOPMENT_HISTORY_2026-11-15.md`。
- 接近上下文或執行限制時，優先保存交接紀錄，不倉促加入大量未驗證修改。
- 未完成工作可保留但不得標示完成；不假設回合結束後仍能背景執行。

```powershell

  '-Dorg.gradle.java.installations.auto-download=false' `
  -jar '.\gradle\wrapper\gradle-wrapper.jar' `
  --no-daemon --max-workers=1 :app:assembleDebug
```

## Codex 建構限制與驗證證據

- Codex 曾因使用者 Gradle 快取存取權限遭拒而建構受阻：存取 `C:\Users\hungg\.gradle\wrapper\dists\...\gradle-9.5.0-bin.zip.lck` 時發生 `AccessDeniedException`，尚未進入 Android 編譯。
- 未有相關環境變更時，不反覆重試相同受阻指令。不擅自刪除快取、搬動快取或 Gradle 使用者目錄，也不變更權限。
- 遇到上述限制時可依授權程序取得既有快取存取權限；若仍受阻，提供完整指令由使用者在一般終端機驗證，並記錄回報結果。
- 回報時清楚區分：
  - **檢查通過**：由本次可取得的檔案檢查或實際指令輸出支持，並註明檢查範圍。
  - **使用者實測通過**：由使用者在其環境實際執行並回報通過，不冒稱為 Codex 本次驗證結果。
  - **尚未驗證**：未執行、證據不足或因環境限制無法完成，明確說明原因。
- 建構成功需有本次指令成功結束、`BUILD SUCCESSFUL` 與 APK 存在的證據；預期 Debug APK 路徑為 `app/build/outputs/apk/debug/app-debug.apk`。
- 既有 APK 不可當作本次建構成功的證據。編譯成功也不等於操作測試通過，兩者分別回報。
